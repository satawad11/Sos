# SOS LoRa — ระบบแจ้งเหตุฉุกเฉินผู้ป่วย (ต้นแบบ → นำร่อง 10 บ้าน)

ปุ่มกดที่บ้านผู้ป่วย (Heltec V3, LoRaWAN AS923) → Gateway (Pi 4B + WM1302) → VPS (ChirpStack + Mosquitto + Backend + แดชบอร์ด) → LINE อสม. ตามลำดับ → เจ้าหน้าที่/อสม. กดรับ → สัญญาณกลับไปที่อุปกรณ์ผู้ป่วย
สัญญาเชื่อมระหว่างส่วนต่าง ๆ: เอกสาร "สัญญากลางระบบแจ้งเหตุฉุกเฉิน LoRaWAN (ต้นแบบ v0.2)"

## สถานะการทดสอบ (ตรงไปตรงมา)
| ส่วน | สถานะ |
|---|---|
| backend (case engine, ACK_L2, escalation, after-hours, LINE webhook, auth/role/lockout, settings→CONFIG) | ✅ เทสต์อัตโนมัติ 67 ข้อ (รวมตั้งค่ารายเครื่อง, provision API, QR, ตรวจเกตเวย์ออฟไลน์/LINE) + end-to-end จริงกับ Mosquitto (กด→รับ→ได้ ACK) |
| dashboard | ✅ ทดสอบใน Chromium (login, ทุกหน้า, เคสขึ้นสีแดง) · ❗ ยังไม่ทดสอบบนมือถือ/จอเล็กและเสียงเตือนจริง |
| Mosquitto TLS + ACL ต่อ gateway | ✅ ทดสอบด้วย mosquitto 2.0.18 (gateway ปลอมหัวข้อของตัวอื่นไม่ได้) |
| ตรวจสุขภาพเกตเวย์ + แจ้ง LINE เมื่อออฟไลน์ | ✅ เทสต์อัตโนมัติ 10 ข้อ + ทดสอบหน้าเว็บใน Chromium + ทดสอบสคริปต์รายงานจริงผ่าน mosquitto 2.0.18 (TLS+ACL) ไปจนถึงตัวถอดรหัสของ backend · ❗ ยังไม่เคยรันบน Pi จริง (vcgencmd/systemd) และยังไม่ส่ง LINE จริง |
| gateway installer | ⚠️ ตรวจ syntax + render config + TOML parse ผ่าน · ❗ ยังไม่เคยรันบน Pi/WM1302 จริง |
| หน้าเว็บ "ติดตั้งอุปกรณ์" (Web Serial) + ตั้งค่ารายเครื่อง | ✅ ทดสอบใน Chromium กับเฟิร์มแวร์จำลอง (สำเร็จ/ล้มแล้ว rollback/ตั้งค่า/รีเซ็ต) · ❗ ยังไม่ทดสอบกับบอร์ด Heltec จริง (พฤติกรรม DTR/RTS ตอนเปิดพอร์ต) และ ChirpStack จริง |
| provision tool | ✅ ยูนิตเทสต์ 5 ข้อ (serial/HTTP จำลอง) · ❗ ยังไม่ได้ลองกับ ChirpStack/บอร์ดจริง |
| docker-compose / ChirpStack config | ⚠️ `docker compose config` ผ่านเท่านั้น **ยังไม่เคยรัน stack จริง** (ไม่มี Docker daemon/เครือข่ายในที่เขียน) — ข้อเสี่ยงที่รู้: การแทน `$ตัวแปร` ใน toml ของ ChirpStack (มีวิธีแก้ใน INSTALL-1) |
| ตำแหน่ง GPS (เกตเวย์/อุปกรณ์) | ✅ backend+แดชบอร์ดทดสอบแล้ว (codec LOC, ห่างบ้าน, เกตเวย์ถูกย้าย) + พาร์เซอร์ NMEA/ตัวเข้ารหัส C++ ทดสอบบนเครื่อง · ❗ เฟิร์มแวร์ GPS ไม่เคยคอมไพล์/ต่อโมดูลจริง, ยังไม่ยืนยันว่า WM1302 รุ่นที่ซื้อมี GPS — ดู `docs/GPS-kit.md` |
| แผนที่ (เมนู "แผนที่") | ✅ แสดงเกตเวย์/อุปกรณ์ + เส้นเชื่อมต่อสีตามคุณภาพสัญญาณ (RSSI/SNR ล่าสุด) — ทดสอบด้วยข้อมูลจำลองแล้ว · ใช้ Leaflet ในโปรเจกต์ (`dashboard/vendor/leaflet`) แต่แผ่นแผนที่พื้นหลังโหลดจาก OpenStreetMap ต้องมีอินเทอร์เน็ตที่เครื่องผู้ใช้ (ส่งเฉพาะชื่อโดเมนเป็น Referer ตามนโยบาย OSM — ถ้า Caddy ตั้ง `Referrer-Policy no-referrer` ไว้ แผ่นแผนที่จะถูกบล็อก 403) · บัญชี "ดูอย่างเดียว" ไม่เห็นพิกัดบ้านผู้ป่วย · เส้นคือ "เกตเวย์ที่ได้ยินล่าสุด" ไม่ใช่เส้นทางจริงของคลื่น |
| ChirpStack จากแดชบอร์ด/โดเมน | ✅ เทสต์อัตโนมัติ (ตัวจำลอง ChirpStack REST): สถานะ, เทียบอุปกรณ์/เกตเวย์, ซิงก์, retired → ปิดใช้งาน, เพิ่มเกตเวย์ → ลงทะเบียนให้ · ❗ **ยังไม่ได้ทดสอบกับ ChirpStack จริง** และ config ของ Caddy ยังไม่ได้ตรวจด้วย Caddy จริง (สคริปต์ตรวจ+ย้อนกลับให้บนเซิร์ฟเวอร์) |
| ตั้งค่า/สั่งงานเกตเวย์จากแดชบอร์ด | ✅ ต่อเกตเวย์: หมายเหตุ, เวลาออฟไลน์, ผู้รับแจ้งเตือน (ผู้ดูแลระบบ) · สั่งงานระยะไกล 4 อย่างผ่านเอเจนต์บน Pi (ขอรายงาน/ดู log/รีสตาร์ท LoRa/รีบูต) ด้วยคำสั่งที่เซ็น HMAC ต่อเกตเวย์ + กันส่งซ้ำ — ทดสอบเอเจนต์แบบ dry-run และหน้าแดชบอร์ดแล้ว **ยังไม่ได้ทดสอบกับ Pi/broker จริง** · ต้องเพิ่มบรรทัด ACL ใน Mosquitto ฝั่งเซิร์ฟเวอร์ ดู `docs/GATEWAY-REMOTE.md` |
| ตารางรายการทุกหน้า | ✅ แบ่งหน้า (ค่าเริ่มต้น 10 รายการ เลือก 10/25/50/100 ได้ จำค่าไว้), ค้นหา, เลือกหลายรายการและทำพร้อมกัน (เปิด/ปิดใช้งาน, ปลดระวาง, ยกเลิกผูก LINE, ลบ) ในหน้าผู้ป่วย/อสม./อุปกรณ์/เกตเวย์/ผู้ใช้ · เคสและบันทึกการใช้งานแบ่งหน้าอย่างเดียว (ไม่มีทำกลุ่มโดยตั้งใจ) · ลบอุปกรณ์/เกตเวย์จะลบใน ChirpStack ด้วย (ถ้าตั้งค่าไว้) |
| ตั้งค่า LINE จากแดชบอร์ด | ✅ เมนู "เชื่อมต่อ LINE" (ผู้ดูแลระบบ): ใส่ Channel access token/secret, ทดสอบการเชื่อมต่อ, ส่งข้อความทดสอบ, คัดลอก Webhook URL · เก็บแบบเข้ารหัสในฐานข้อมูล ไม่แสดงกลับ ไม่อยู่ใน audit · มีผลทันที · ค่าใน .env ยังใช้เป็นค่าสำรอง · **ทดสอบกับ LINE จำลองเท่านั้น ยังไม่ได้ลองกับบัญชี LINE จริง** |
| แจ้งเตือน LINE เมื่อปุ่มเงียบ/แบตต่ำ/ไฟดับ | ✅ เทสต์อัตโนมัติ 6 ข้อ + ทดสอบหน้าตั้งค่าใน Chromium · ❗ ยังไม่ส่ง LINE จริง |
| รหัสผ่าน/ผู้ใช้/รายงาน/PDPA | ✅ เทสต์อัตโนมัติ 67 ข้อ + ทดสอบหน้าเว็บใน Chromium (เปลี่ยนรหัสบังคับ, รีเซ็ต, ยินยอม/ถอน/ส่งออก/ลบข้อมูล, รายงาน+CSV, viewer บนจอมือถือ) · ❗ ไม่ใช่คำปรึกษากฎหมาย — ดู `docs/PDPA.md` |
| **firmware** | ⚠️ **ยังไม่เคยคอมไพล์/รันบนบอร์ด** — ตรวจ API กับซอร์ส RadioLib 7.2.1 แล้ว (beginOTAA/activateOTAA/sendReceive/NONCES buffer/`LoRaWANEvent_t.confirming,fPort`/AS923) |
| LINE จริง | ❗ ยังไม่ทดสอบกับ LINE API จริง (ทดสอบด้วย webhook จำลอง + ตรวจลายเซ็น) |
| ประสิทธิภาพ/ระยะ/แบตเตอรี่ | ❗ ยังไม่วัด — ต้องวัดตอนต้นแบบ |
