# จัดการ ChirpStack จากระบบ SOS และผ่านโดเมน

มีสองทาง ใช้คู่กันได้:

| ทาง | ใช้ทำอะไร | ใครใช้ |
|---|---|---|
| **หน้า "ChirpStack" ในแดชบอร์ด** | ดูสถานะการเชื่อมต่อ เทียบข้อมูลอุปกรณ์/เกตเวย์ และกดซิงก์ | ผู้ดูแลระบบ (admin) |
| **โดเมนของ ChirpStack** เช่น `https://lns.dmtc.ac.th` | ตั้งค่าเชิงลึก (Device profile, ดู LoRaWAN frames, debug การ join) | ผู้ดูแลระบบ จากเครือข่ายที่อนุญาตเท่านั้น |

## 1. ระบบ SOS ทำอะไรใน ChirpStack ให้เองบ้าง

| ทำในแดชบอร์ด | ระบบทำใน ChirpStack ให้ |
|---|---|
| ติดตั้งอุปกรณ์ (หน้า "ติดตั้งอุปกรณ์") | สร้าง device + ใส่ AppKey (มีอยู่เดิม) |
| เพิ่มเกตเวย์ (หน้า "เกตเวย์") | ลงทะเบียน gateway ใน ChirpStack พร้อมพิกัด (ถ้ามี) |
| ตั้งอุปกรณ์เป็น **ปลดระวาง (retired)** | **ปิดใช้งาน** device ใน ChirpStack (uplink ถูกทิ้ง) |
| เปลี่ยนจาก retired เป็นสถานะอื่น | เปิดใช้งานกลับ |
| กด **ซิงก์** ที่หน้า ChirpStack | ลงทะเบียนเกตเวย์ที่ยังขาด + แก้สถานะเปิด/ปิดที่ไม่ตรง |

- ถ้า ChirpStack ล่มตอนบันทึก ข้อมูลในแดชบอร์ด**ยังบันทึกได้ตามปกติ** มีข้อความเตือน และลงบันทึกการใช้งาน → กดซิงก์ภายหลัง
- ระบบ**ไม่สร้างหรือลบ device ใน ChirpStack ตอนซิงก์** เพราะ AppKey อยู่บนตัวปุ่มกับ ChirpStack เท่านั้น
  - "มีในแดชบอร์ดแต่ไม่มีใน ChirpStack" → ลงทะเบียนใหม่ที่หน้าติดตั้งอุปกรณ์
  - "มีใน ChirpStack แต่ไม่มีในแดชบอร์ด" → กดปุ่มแล้วไม่มีใครได้รับแจ้ง ต้องเพิ่มในหน้าอุปกรณ์หรือลบออกจาก ChirpStack
- API key `provision` (ของ Tenant) ใช้ได้กับทุกงานข้างบน ไม่ต้องสร้างคีย์ใหม่

## 2. เปิดหน้า ChirpStack ผ่านโดเมน

1. **DNS:** เพิ่ม A record `lns.dmtc.ac.th` → IP เดียวกับ `sos.dmtc.ac.th` (เช่น `202.29.228.8`) — พอร์ต 80/443 forward มาที่เครื่องเดียวกันอยู่แล้ว
   ใช้ Cloudflare แบบเมฆสีส้ม (Proxy) หรือสีเทา (DNS only) ก็ได้: Caddy เชื่อ IP ผู้ใช้จาก header `CF-Connecting-IP`
   เฉพาะคำขอที่มาจาก IP ของ Cloudflare จริง (`trusted_proxies` ใน `infra/caddy/Caddyfile`) — แบบสีเทาง่ายกว่าและไม่ติด timeout ของ Cloudflare
   ถ้าเคยเห็น `Forbidden: 172.6x.x.x` / `162.158.x.x` (IP ของ Cloudflare) → อัปเดตระบบแล้วรันสคริปต์ข้อ 2 อีกครั้ง
2. บนเซิร์ฟเวอร์ (CT100):
   ```bash
   cd /opt/sos/infra
   sudo bash scripts/enable-chirpstack-domain.sh lns.dmtc.ac.th 202.29.228.0/28 10.0.0.0/8
   ```
   - ตามด้วย IP/ช่วง IP ที่อนุญาตให้เปิดหน้านี้ (ใส่ได้หลายช่วง) ถ้าไม่ใส่ จะอนุญาตเฉพาะเครือข่ายภายใน (10/8, 172.16/12, 192.168/16)
   - สคริปต์ตรวจ config ของ Caddy ก่อน ถ้าผิดจะย้อนกลับให้อัตโนมัติ · Caddy ขอใบรับรอง HTTPS ให้เอง
3. เปิด `https://lns.dmtc.ac.th` → ถ้ายังเป็น `admin/admin` **เปลี่ยนรหัสผ่านทันที**
4. ในแดชบอร์ด หน้า ChirpStack จะมีปุ่ม "เปิดหน้า ChirpStack"
5. แผนที่เกตเวย์ในหน้า ChirpStack โหลดภาพแผนที่ผ่านเซิร์ฟเวอร์เรา (`/osm-tiles/…` บนโดเมนนี้ ตั้งใน `infra/chirpstack/chirpstack.toml` ส่วน `[ui]`)
   เพราะ OpenStreetMap บล็อกการขอภาพจากหน้าเว็บ ChirpStack โดยตรง ("Access blocked") — path นี้อยู่หลัง allow-list เดียวกัน
   และระบุชื่อระบบตามนโยบายของ OSM · ถ้าเปิดผ่าน SSH tunnel แผนที่จะเป็นสีเทา (ส่วนอื่นใช้ได้ปกติ)

ปิดกลับเป็นแบบ SSH tunnel อย่างเดียว: `sudo bash scripts/enable-chirpstack-domain.sh --disable`

> ⚠️ อย่าเปิดหน้านี้ให้ทุก IP — ใครเข้าได้จะลบอุปกรณ์หรือเปลี่ยนค่าเครือข่ายได้ทั้งหมด
> ถ้าเข้าจากนอกวิทยาลัย ให้ใช้ VPN เข้ามาก่อน หรือใช้ SSH tunnel (`ssh -L 8080:localhost:8080 ...`) เหมือนเดิม
> ถ้าได้ 403 ทั้งที่อยู่ในวิทยาลัย: IP ที่เซิร์ฟเวอร์เห็นอาจเป็น IP ขาออก (NAT) ของวิทยาลัย → ใส่ IP นั้นแทน
