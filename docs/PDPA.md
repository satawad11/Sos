# การจัดการข้อมูลส่วนบุคคล (PDPA) ในระบบแจ้งเหตุฉุกเฉิน

> **ข้อสำคัญ:** เอกสารนี้อธิบายว่าระบบ "ทำอะไรได้" ไม่ใช่คำปรึกษากฎหมาย ผู้ควบคุมข้อมูล (รพ.สต./อบต.) ต้องให้เจ้าหน้าที่คุ้มครองข้อมูล (DPO) หรือฝ่ายกฎหมายของตนยืนยันระยะเวลาเก็บ ข้อความขอความยินยอม และหน้าที่แจ้งเหตุละเมิดข้อมูลเอง

## 1. ข้อมูลที่ระบบเก็บ
| ข้อมูล | ตัวอย่าง | อ่อนไหว? | เก็บที่ไหน | ใครเห็น |
|---|---|---|---|---|
| ตัวตนผู้ป่วย | ชื่อ อายุ ที่อยู่ หมู่บ้าน เบอร์โทร | ข้อมูลทั่วไป | PostgreSQL | admin/staff (viewer เห็นชื่อ+หมู่บ้าน เบอร์ปิดบังเหลือ 4 ตัวท้าย) |
| หมายเหตุสุขภาพ | โรคประจำตัว ข้อควรระวัง (ช่อง notes) | **ข้อมูลสุขภาพ (ม.26)** | PostgreSQL | admin/staff · แนะนำให้ใส่เท่าที่จำเป็นต่อการช่วยเหลือ |
| พิกัดบ้าน | lat/lon | อ่อนไหวทางอ้อม | PostgreSQL | admin/staff |
| ตำแหน่งอุปกรณ์ (GPS, ถ้าติดตั้ง) | ตำแหน่งล่าสุด + ดาวเทียม + HDOP | อ่อนไหว | ล่าสุดต่ออุปกรณ์/ต่อเคส เท่านั้น (ไม่เก็บเส้นทาง) | admin/staff |
| ประวัติเคส | เวลา ผู้รับเรื่อง ผลการปิดเคส | ข้อมูลสุขภาพโดยนัย | PostgreSQL | admin/staff |
| บันทึกการใช้งาน (audit) | ใครทำอะไรเมื่อไร | – | PostgreSQL | admin |
| ข้อความ LINE | ชื่อ+ที่อยู่ผู้ป่วย ส่งถึง อสม. | **ส่งไปยังผู้ให้บริการ LINE (ต่างประเทศ)** | LINE | ผู้รับ |

พิกัดไม่ถูกเขียนลงไทม์ไลน์ของเคส (เก็บเฉพาะจำนวนดาวเทียม ค่า HDOP และระยะห่างจากบ้าน)

## 2. สิ่งที่ระบบทำให้
- **บันทึกความยินยอมรายคน** (หน้า "ผู้ป่วย" → "ข้อมูล/PDPA"): ผู้บันทึก เวลา และหมายเหตุ (เลขที่แบบฟอร์ม/ผู้ให้ความยินยอมแทน)
- **ด่านความยินยอม:** ตั้งอุปกรณ์เป็น `active` ให้ผู้ป่วยที่ไม่มีบันทึกยินยอมไม่ได้ (ปิดได้ที่ "PDPA → นโยบาย" แต่ไม่แนะนำ)
- **ถอนความยินยอม:** ปิดผู้ป่วย, คืนอุปกรณ์เป็น `ready`, ลบรายชื่อผู้ดูแลที่ผูก, ล้างตำแหน่งอุปกรณ์
- **ส่งออกข้อมูล** (admin): JSON ครบทุกอย่างที่เก็บเกี่ยวกับผู้ป่วยรายนั้น ใช้ตอบคำขอเข้าถึง/โอนย้ายข้อมูล
- **ลบข้อมูลที่ระบุตัวตน** (admin, ย้อนกลับไม่ได้): ชื่อ/อายุ/ที่อยู่/เบอร์/พิกัด/หมายเหตุถูกล้าง เคสเก่าเหลือเฉพาะสถิติ (เลือกคงชื่อหมู่บ้านไว้ได้) ต้องพิมพ์เลขที่ผู้ป่วยยืนยัน และต้องไม่มีเคสเปิดค้าง
- **ระยะเวลาเก็บ:** เคสที่ปิดแล้วเกิน 730 วัน (ตั้งได้ 30–3650), เคสทดสอบเกิน 30 วัน, audit เกิน 365 วัน (ตั้งได้ 90–3650; บันทึกด้านความยินยอม/ส่งออก/ลบข้อมูลเก็บไว้เสมอ) — ลบเองด้วยปุ่ม (ดูตัวอย่างก่อน) หรือเปิด "ลบอัตโนมัติทุกชั่วโมง"
- **ข้อความ LINE แบบน้อยที่สุด:** ชื่อ+หมู่บ้านเท่านั้น ไม่มีปุ่มโทร/นำทาง ไม่ส่งตำแหน่งตามหลัง
- **สิทธิ์ผู้ใช้:** `viewer` ไม่เห็นที่อยู่ หมายเหตุ พิกัด ตำแหน่งอุปกรณ์ และรายชื่อผู้ป่วยที่แจ้งบ่อย
- **รหัสผ่าน:** ≥10 ตัว, ห้ามมีชื่อผู้ใช้/รหัสเดาง่าย, ล็อกบัญชี 15 นาทีหลังผิด 5 ครั้ง, รหัสชั่วคราวแสดงครั้งเดียวและต้องเปลี่ยนทันที, เปลี่ยนรหัส/สิทธิ์แล้วทุกเครื่องถูกออกจากระบบ

## 3. สิ่งที่ระบบ **ไม่ได้** ทำ — ต้องมีคนรับผิดชอบ
1. กำหนดว่า **ใครคือผู้ควบคุมข้อมูล** (รพ.สต. หรือ อบต. หรือร่วมกัน) และแต่งตั้ง DPO ถ้าจำเป็น
2. หนังสือยินยอมที่ถูกต้องตามกฎหมาย (ตัวอย่างข้อ 4 เป็นแค่แนวทาง)
3. ข้อตกลงกับผู้ให้บริการ (LINE, DigitalOcean) และประเมินการส่งข้อมูลไปต่างประเทศ (เซิร์ฟเวอร์อยู่สิงคโปร์) — ถ้าหน่วยงานกำหนดให้เก็บในประเทศ ต้องย้าย VPS
4. กระบวนการแจ้งเหตุละเมิดข้อมูล (ภายใน 72 ชม. ตามที่กฎหมายกำหนด) และการสำรอง/เข้ารหัสดิสก์
5. อีเมลรีเซ็ตรหัสผ่าน — **ไม่มี** (ไม่มีระบบอีเมล) ใช้ผู้ดูแลระบบรีเซ็ต หรือคำสั่งบนเซิร์ฟเวอร์ `python -m app.cli reset-password <ผู้ใช้>`
6. ข้อมูลที่ส่งไป LINE แล้ว ระบบลบให้ไม่ได้

## 4. แนวทางข้อความหนังสือยินยอม (ร่าง — ให้ฝ่ายกฎหมายตรวจ)
> ข้าพเจ้า ............ ยินยอมให้ [ชื่อหน่วยงาน] เก็บและใช้ ชื่อ ที่อยู่ เบอร์โทร ข้อมูลสุขภาพที่จำเป็น และตำแหน่งของอุปกรณ์แจ้งเหตุ เพื่อ **การช่วยเหลือฉุกเฉินเท่านั้น** โดยจะแจ้งข้อมูลดังกล่าวแก่ อสม./เจ้าหน้าที่ที่เกี่ยวข้อง ผ่านระบบข้อความ **LINE ซึ่งผู้ให้บริการอยู่ต่างประเทศ** และเก็บข้อมูลไว้ไม่เกิน ..... ปี ข้าพเจ้ามีสิทธิ์ขอดู ขอสำเนา แก้ไข หรือถอนความยินยอมได้ทุกเมื่อโดยแจ้ง ............ (การถอนความยินยอมทำให้ใช้อุปกรณ์แจ้งเหตุไม่ได้)
> ผู้ให้ความยินยอม ............ ความสัมพันธ์ (ถ้าให้แทน) ............ วันที่ ............

## 5. ขั้นตอนใช้งานประจำ
- ผู้ป่วยใหม่: เพิ่มผู้ป่วย → ลงนามหนังสือยินยอม → "ข้อมูล/PDPA" → บันทึกความยินยอม (ใส่เลขที่แบบฟอร์ม) → กำหนดผู้ดูแล → ตั้งอุปกรณ์ active
- ขอข้อมูล: "ข้อมูล/PDPA" → ส่งออก (admin)
- ขอลบ/ถอน: ถอนความยินยอมก่อน (หยุดใช้งานทันที) แล้วค่อยลบข้อมูลที่ระบุตัวตนเมื่อไม่มีเคสค้าง
- ทุกเดือน: หน้า "PDPA" ดูรายชื่อที่ยังไม่มีบันทึกยินยอม และตัวอย่างข้อมูลที่เกินระยะเก็บ
