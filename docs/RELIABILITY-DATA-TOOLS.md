# ความทนทานของการแจ้งเตือน และเครื่องมือจัดการข้อมูล

เอกสารนี้อธิบายสิ่งที่เพิ่มในรุ่นนี้ และสิ่งที่ต้องตั้งค่าเองบนเซิร์ฟเวอร์หลังอัปเดต

## สิ่งที่ต้องทำหลังอัปเดต (ครั้งเดียว)

1. **เข้ารหัสไฟล์สำรอง** — สร้างไฟล์กุญแจ แล้วเก็บสำเนากุญแจไว้ที่อื่นด้วย (ไม่มีกุญแจ = กู้ไฟล์ที่เข้ารหัสไม่ได้)
   ```bash
   sudo install -d -m 700 /etc/sos
   sudo sh -c 'openssl rand -base64 48 > /etc/sos/backup.key && chmod 600 /etc/sos/backup.key'
   ```
2. **ส่งสำเนานอกเครื่อง** — สร้าง `/etc/default/sos-backup` แล้วใส่ปลายทางอย่างใดอย่างหนึ่ง (ส่งเฉพาะไฟล์ที่เข้ารหัสแล้ว)
   ```bash
   BACKUP_REMOTE=rclone:gdrive:sos-backup        # rclone remote ที่ตั้งไว้แล้ว
   BACKUP_REMOTE=scp:backup@10.0.0.5:/srv/sos    # หรือเครื่องอื่นผ่าน ssh key
   ```
3. **ตรวจว่ามี cron สำรองทุกวัน** — `0 2 * * * /opt/sos/infra/scripts/backup.sh >> /var/log/sos-backup.log 2>&1`
4. **ตั้งตัวเฝ้าจากภายนอก** ที่เมนู “สถานะระบบ” (อย่างน้อย 1 อย่าง)
   - วาง URL จากบริการแบบ dead-man's switch (เช่น healthchecks.io) ระบบจะส่งสัญญาณชีพเฉพาะตอนที่ทุกส่วนปกติ
   - หรือรัน `infra/scripts/watchdog.sh` ด้วย cron จากเครื่องอื่น / ตั้ง uptime monitor ชี้มาที่ `/healthz?strict=1`

ทดสอบกู้คืนอย่างน้อย 1 ครั้ง: `sudo infra/scripts/restore.sh /var/backups/sos/sos-YYYYMMDD-HHMM.dump.enc`

## การแจ้งเตือน LINE

- ข้อความ LINE ถูกเข้าคิว (`sos_outbox`) ในธุรกรรมเดียวกับเคส แล้วส่งโดย worker แยก จึงไม่ถ่วงการรับสัญญาณจากปุ่มและการส่ง ACK
- ส่งไม่ผ่านจะลองใหม่อีก 4 ครั้ง (หลัง 5, 15, 30, 60 วินาที) ข้อผิดพลาดถาวร (HTTP 400/401/403) ไม่ลองซ้ำ
- ถ้าส่งถึงผู้ดูแลคนนั้นไม่ได้เลย เคสจะถูกส่งต่อคนถัดไป **ทันที** ไม่รอครบเวลา escalation และมีเหตุการณ์ `notify_failed` ในเคส
- เคสที่มีคนรับเรื่องแล้วจะไม่ถูกส่งซ้ำ ข้อความที่ค้างเกิน 30 นาทีจะถูกทิ้ง

## /healthz

| URL | ใช้กับ | ล้มเหลว (503) เมื่อ |
|---|---|---|
| `/healthz` | ตัวอัปเดต, Docker | ฐานข้อมูลใช้ไม่ได้ หรือลูปจัดการเคสหยุด |
| `/healthz?strict=1` | uptime monitor, watchdog.sh | ข้างต้น + MQTT ขาดเกิน 2 นาที + คิว LINE ค้างเกิน 5 นาที |

รายละเอียด (คิว LINE, สถานะ backup, heartbeat) อยู่ที่ `GET /api/system/health` เฉพาะผู้ดูแลระบบ

## ข้อมูล

- **สถิติผู้ป่วยรายบุคคล** — หน้าผู้ป่วย กดชื่อหรือปุ่ม “สถิติ”
- **ภาระงาน อสม.** — หน้า อสม./ผู้ดูแล แสดงจำนวนผู้ป่วยที่ดูแล (หลัก/สำรอง) และผู้ป่วยที่ยังไม่มีผู้ดูแล
- **ความพร้อมข้อมูล** — เมนูใหม่ บอกว่าผู้ป่วยรายใดยังขาดอะไร เรียงจากรายที่เสี่ยงแจ้งเหตุไม่ถึงก่อน
- **ค้นหาประวัติเคส** — หน้าเคสฉุกเฉิน ปุ่ม “ค้นหาประวัติเคสทั้งหมด” กรองตามวันที่ สถานะ ผล หมู่บ้าน ชื่อ/ปุ่ม/เลขเคส
- **นำเข้าจากไฟล์** — หน้าผู้ป่วยและหน้า อสม. รับไฟล์ CSV (บันทึกจาก Excel เป็น “CSV UTF-8”) หรือวางตารางจาก Excel ได้ครั้งละไม่เกิน 1,000 แถว ระบบตรวจก่อนบันทึก ชื่อที่มีอยู่แล้วจะถูกข้าม ไม่เขียนทับ ผู้ป่วยที่นำเข้ายังไม่มีบันทึกความยินยอม
- **ประวัติอุปกรณ์** — หน้าอุปกรณ์ ปุ่ม “ประวัติ” แสดงกราฟแบตเตอรี่/สัญญาณ แนวโน้มแบต และดาวน์โหลด CSV เก็บ 400 วัน (เริ่มเก็บตั้งแต่อัปเดตรุ่นนี้)
- **รายงานเกตเวย์** — ช่วงเวลาที่เกตเวย์ล่ม/ซ่อมบำรุงเก็บใน `sos_state_log` ซึ่งไม่ถูกลบตามอายุ audit log รายงานเดือนเก่าจึงไม่เปลี่ยนค่า

## ฐานข้อมูล (สำหรับผู้พัฒนา)

ตอนเริ่มระบบ `app.db.migrate()` ทำ 2 ชั้น: `create_all()` + `ensure_columns()` เหมือนเดิม (ตารางใหม่และคอลัมน์ใหม่ที่ nullable เพิ่มเองได้) แล้วตามด้วย Alembic (`backend/app/migrations/versions/`) สำหรับสิ่งที่ชั้นแรกทำไม่ได้ เช่น index บนตารางเดิม การย้ายข้อมูล การเปลี่ยนชนิดคอลัมน์ สคริปต์ migration ต้องรันซ้ำได้ (ใช้ตัวช่วยใน `migrations/util.py`) ฐานข้อมูลเดิมจะถูกรับเข้า Alembic อัตโนมัติ

## โครงสร้างไฟล์ (สำหรับผู้พัฒนา)

ไฟล์ใหญ่สองไฟล์ถูกแยกตามหมวด โดยไม่เปลี่ยน URL ของ API และไม่เปลี่ยนพฤติกรรมของหน้าเว็บ

| เดิม | ตอนนี้ |
|---|---|
| `backend/app/api.py` (ราว 1,960 บรรทัด) | `api.py` = เคส ผู้ป่วย อสม. และตัวช่วยที่ใช้ร่วมกัน · `api_auth.py` เข้าสู่ระบบ/2FA · `api_devices.py` ปุ่ม เกตเวย์ แผนที่ · `api_admin.py` ตั้งค่า ผู้ใช้ audit รายงาน · `api_line.py` LINE · `api_ai.py` AI · `api_setup.py` ติดตั้งอุปกรณ์ ChirpStack เฟิร์มแวร์ · `api_app.py` Web Push ทดสอบปุ่ม อัปเดตระบบ |
| `dashboard/index.html` (ราว 2,370 บรรทัด) | `index.html` (โครงหน้า) + `app.css` + `js/core.js` `cases.js` `people.js` `network.js` `system.js` `install.js` `admin.js` โหลดตามลำดับนี้และใช้ตัวแปรร่วมกัน |

เซิร์ฟเวอร์ส่ง `Cache-Control: no-cache` กับ `index.html`, `app.css` และ `js/*.js` เบราว์เซอร์จึงตรวจกับเซิร์ฟเวอร์ทุกครั้ง หลังอัปเดตจะไม่เจอหน้าเว็บรุ่นใหม่คู่กับสคริปต์รุ่นเก่า ส่วนฟอนต์ ไอคอน และไลบรารีใน `vendor/` ยังแคชได้ตามเดิม

หน้าเว็บ: หน้าเคส อุปกรณ์ และเกตเวย์ วาดใหม่จากเหตุการณ์สด (WebSocket) การดึงข้อมูลซ้ำเหลือทุก 60 วินาทีเป็นตัวสำรอง และกลับเป็นทุก 15 วินาทีเฉพาะตอนการเชื่อมต่อสดหลุด
