# อัปเดตเฟิร์มแวร์ปุ่มผ่านหน้าเว็บ (USB)

อัปเดตโปรแกรมในปุ่ม Heltec ได้จากหน้า **ติดตั้งอุปกรณ์ → อัปเดตเฟิร์มแวร์ผ่าน USB** ด้วย Chrome หรือ Edge บนคอมพิวเตอร์
ไม่ต้องลง PlatformIO และไม่ต้องติดตั้งคีย์ใหม่

## ทำไมต้องเสียบสาย USB

ไฟล์เฟิร์มแวร์ขนาดประมาณ 1 MB ส่งผ่านคลื่น LoRa ไม่ได้จริง เพราะส่งได้ครั้งละไม่กี่ร้อยไบต์และต้องเว้นช่วงตามกติกาย่าน AS923
ถ้าส่งทางนี้จะใช้เวลาหลายวันต่อเครื่อง ส่วน**การตั้งค่าเครื่อง** (heartbeat, เสียงบัซเซอร์, เวลากดค้าง) ยังส่งผ่าน LoRa
จากหน้าอุปกรณ์ได้ตามเดิม

## ไฟล์เฟิร์มแวร์มาจากไหน

1. ทุกครั้งที่มีการ push ขึ้น `main` ขั้นตอน `firmware-publish` ใน GitHub Actions (`.github/workflows/ci.yml`) จะ build
   `heltec_v2`, `heltec_v3` และ `heltec_v3_gps` แล้วเก็บเฉพาะไฟล์โปรแกรม (`<env>.bin`) และ `manifest.json`
   (เวอร์ชัน, ขนาด, SHA-256, MD5) ไว้ใน branch **`firmware-bin`** เป็น commit เดียวที่เขียนทับทุกครั้ง branch จึงไม่โตขึ้นเรื่อยๆ
2. บนเซิร์ฟเวอร์ `infra/scripts/sos-update.sh` ดึง branch นี้มาวางไว้ที่ `infra/update/firmware/` ทุกครั้งที่กด
   **ตรวจหาเวอร์ชันใหม่** หรือ **อัปเดตระบบ** โดยใช้สิทธิ์ git ชุดเดียวกับที่ดึงโค้ด (repo เป็น private จึงไม่ต้องเพิ่ม token)
   ถ้าการ์ดขึ้นว่ายังไม่มีไฟล์ ผู้ดูแลระบบกด **ดึงไฟล์เฟิร์มแวร์จาก GitHub** บนการ์ดได้เลย
3. backend ส่งไฟล์ให้หน้าเว็บผ่าน `/api/firmware` และ `/api/firmware/<env>.bin` ให้เฉพาะ staff และ admin

## ขั้นตอนบนหน้าเว็บ

| ขั้น | สิ่งที่ระบบทำ |
|---|---|
| 1. เชื่อมต่อและอ่านข้อมูลเครื่อง | ส่งคำสั่ง `INFO` เพื่ออ่านเวอร์ชันเดิมและ DevEUI แล้วจับคู่กับรายการอุปกรณ์ ถ้าเครื่องไม่ตอบ (เช่น ยังไม่มีเฟิร์มแวร์) ก็อัปเดตต่อได้ |
| 2. เข้าโหมดอัปเดตและตรวจชิป | esptool-js รีเซ็ตเครื่องเข้า bootloader แล้วอ่านชนิดชิป ESP32 ใช้ไฟล์ `heltec_v2` ส่วน ESP32-S3 ใช้ `heltec_v3` หรือ `heltec_v3_gps` (ถ้าเครื่องเคยส่งพิกัด GPS จะเลือกตัว GPS ให้) ถ้าเลือกบอร์ดเองแต่ไม่ตรงกับชิป ระบบจะหยุดก่อนเขียน |
| 3. ดาวน์โหลดและตรวจไฟล์ | ตรวจขนาดและ SHA-256 ให้ตรงกับ `manifest.json` ถ้าเครื่องใช้เวอร์ชันนี้อยู่แล้วจะถามยืนยันก่อนเขียนทับ |
| 4. เขียนเฟิร์มแวร์ | เขียนเฉพาะไฟล์โปรแกรมที่ `0x10000` แล้วตรวจ MD5 ของข้อมูลในหน่วยความจำ flash เทียบกับไฟล์ ส่วน bootloader, ตารางพาร์ทิชัน และ NVS (ที่เก็บคีย์ LoRaWAN และค่าตั้ง) ไม่ถูกแตะ |
| 5. รีสตาร์ตและยืนยันเวอร์ชันใหม่ | อ่าน `INFO` อีกครั้ง เวอร์ชันต้องตรงกับที่เขียนและ DevEUI ต้องเป็นค่าเดิม บอร์ดที่ใช้ USB ในตัวชิปจะได้พอร์ตใหม่หลังรีสตาร์ต ระบบจะหาพอร์ตนั้นให้เอง |

ทุกครั้งที่อัปเดตจะบันทึกใน audit log เป็น `firmware_flash` หรือ `firmware_flash_failed` พร้อมเวอร์ชันเดิม/ใหม่และชื่อบอร์ด
ช่องเฟิร์มแวร์ของเครื่องในหน้าอุปกรณ์จะเปลี่ยนทันที ส่วนในหน้ารายการอุปกรณ์ เครื่องที่ยังใช้เวอร์ชันเก่าจะมีป้ายสีส้ม **มี x.y**

## ถ้าเจอปัญหา

- **เปิดพอร์ตไม่ได้:** ปิด Serial Monitor, PlatformIO หรือแท็บอื่นที่เปิดพอร์ตนี้อยู่
- **เข้าโหมดอัปเดตไม่ได้:** กดปุ่ม **PRG** ค้างไว้ แล้วกด **RST** หนึ่งครั้ง จากนั้นปล่อย PRG แล้วกดเริ่มอัปเดตใหม่
- **เขียนไม่สำเร็จหรือสายหลุดกลางทาง:** bootloader ยังอยู่ เครื่องจึงเข้าโหมดอัปเดตได้เสมอ ให้กดเริ่มอัปเดตใหม่
- **เครื่องรีสตาร์ตแล้วรายงานเวอร์ชันเดิม:** ถอดสายแล้วเสียบใหม่ แล้วลองอีกครั้ง ถ้ายังเป็นเหมือนเดิมให้ดู Actions ว่า build ล่าสุดผ่านหรือไม่
- **บอร์ดใหม่ที่ไม่เคยลงเฟิร์มแวร์ของระบบนี้:** ครั้งแรกให้ลงด้วย PlatformIO ตาม `docs/INSTALL-3-device-firmware.md`
  เพื่อให้ได้ตารางพาร์ทิชันที่ถูกต้อง ครั้งต่อไปจึงอัปเดตจากหน้าเว็บได้
