# ติดตั้งที่ 3: อุปกรณ์ผู้ป่วย (Heltec WiFi LoRa 32 V3) — ฮาร์ดแวร์ + firmware

> ⚠️ **สถานะ firmware: เขียนและตรวจชื่อ API กับซอร์ส RadioLib 7.2.1 แล้ว แต่ "ยังไม่เคยคอมไพล์/รันบนบอร์ดจริง"** (สภาพแวดล้อมที่เขียนไม่มี PlatformIO registry/บอร์ด) คาดว่าจะต้องแก้เล็กน้อยตอนคอมไพล์ครั้งแรก ต้องผ่านการทดสอบบนโต๊ะ (ข้อ 5) ครบก่อนนำไปวางที่บ้านผู้ป่วย — **อุปกรณ์นี้ไม่ใช่เครื่องมือแพทย์ ต้องมีช่องทางสำรอง (โทร 1669) เสมอ**

เวลา ~2–3 ชั่วโมงต่อเครื่องแรก (เครื่องถัดไป ~10 นาที)

## 1. อุปกรณ์ที่ต้องมี (ต่อ 1 เครื่อง)
| ชิ้น | หมายเหตุ |
|---|---|
| Heltec WiFi LoRa 32 V3 (ESP32-S3 + SX1262, ย่าน 863–928 MHz) พร้อมเสา | **ต้องต่อเสาก่อนจ่ายไฟ** |
| ปุ่มกดใหญ่ (normally-open) | ต่อ GPIO4 ↔ GND |
| LED แดง + 330 Ω → GPIO5 · LED เขียว + 330 Ω → GPIO6 | ขั้วลบลง GND |
| Buzzer แบบ **active** 5V + ทรานซิสเตอร์ NPN (2N2222/BC547) | GPIO7 → 1 kΩ → ฐาน, อีมิตเตอร์ GND, buzzer ระหว่าง 5V กับคอลเลกเตอร์ + ไดโอด 1N4148 คร่อม buzzer |
| ตัวแบ่งแรงดันตรวจไฟบ้าน: 5V (USB) → 10 kΩ → GPIO3 → 20 kΩ → GND | GPIO3 = HIGH เมื่อมีไฟ USB (ได้ ~3.3V) |
| แบตเตอรี่ LiPo 3.7V 1000–2000 mAh มีวงจรป้องกัน (ขั้ว JST 1.25 ของบอร์ด) | ตรวจขั้วบวก/ลบตรงกับบอร์ดก่อนเสียบ (สลับ = เสียหาย) |
| อะแดปเตอร์ USB 5V/1A + สาย, กล่องพลาสติก | |
ต้นทุนคาดการณ์ ~ 900–1,300 บาท/เครื่อง (ตรวจราคาจริงก่อนสั่งหลายเครื่อง)

**ยืนยันผังขากับบอร์ดรุ่นของคุณ** (V3 / V3.1 / V3.2): ขา LoRa/OLED ใน `firmware/include/config.h` ตรงกับผังของ Heltec V3 · ขา `ADC_Ctrl` (GPIO37) ใช้เปิดตัวแบ่งแรงดันแบตเตอรี่ — ถ้าค่าแบตที่อ่านเพี้ยน ให้เปลี่ยน `ADC_CTRL_ACTIVE_LEVEL` เป็น `HIGH` และปรับ `VBAT_DIVIDER` โดยวัดแรงดันจริงด้วยมัลติมิเตอร์

## 2. ติดตั้งเครื่องมือบนคอมพิวเตอร์
1. ติดตั้ง **VS Code** + ส่วนเสริม **PlatformIO IDE** (หรือ `pip install platformio`)
2. ไดรเวอร์ USB: Heltec V3 ใช้ USB-C native (ESP32-S3) — Windows/macOS/Linux ปกติไม่ต้องลงเพิ่ม ถ้า port ไม่ขึ้นให้กดค้างปุ่ม **PRG** แล้วกด RST เพื่อเข้าโหมดดาวน์โหลด

## 3. คอมไพล์และอัปโหลด
```bash
cd sos/firmware
pio run                          # ครั้งแรกดาวน์โหลด toolchain + RadioLib 7.2.1 + U8g2 (ต้องมีอินเทอร์เน็ต)
pio run -t upload                # เสียบ USB-C แล้วอัปโหลด
pio device monitor               # ดู log ที่ 115200
```
ถ้าคอมไพล์ไม่ผ่าน: ส่งข้อความ error มา — จุดเสี่ยงที่รู้ตัวคือชื่อ enum/ชนิดข้อมูลเล็กน้อยและเวอร์ชัน arduino-esp32

ครั้งแรกบอร์ดจะแสดง **NOT SETUP** (LED แดง/เขียวกระพริบสลับ) = ปกติ ยังไม่มีกุญแจ → ไปขั้นที่ 4 (ติดตั้งที่ 4: provision)

## 4. ใส่กุญแจ (provision)
ทำตาม `INSTALL-4-provision.md` — เครื่องมือจะสร้าง DevEUI/AppKey, ลงทะเบียนที่ ChirpStack + backend แล้วเขียนกุญแจเข้าบอร์ดทาง USB อัตโนมัติ · บอร์ดรีสตาร์ท → LED เขียวกะพริบช้า (กำลัง join) → กะพริบสั้นทุก 5 วินาที = **พร้อมใช้ (READY)**

## 5. ทดสอบบนโต๊ะ (ต้องผ่านทุกข้อก่อนนำไปติดตั้ง)
เตรียม: gateway ทำงาน, ในแดชบอร์ดตั้งอุปกรณ์เป็น `active` และผูกผู้ป่วยทดสอบ + มี อสม. ทดสอบที่ผูก LINE แล้ว (INSTALL-5)

| # | ทดสอบ | ผลที่ต้องได้ |
|---|---|---|
| 1 | จ่ายไฟครั้งแรก | OLED ขึ้น CONNECTING → READY ภายใน ≤ 2 นาที; ChirpStack เห็น Join |
| 2 | กดปุ่มสั้น < 1 วินาที | **ไม่ส่งสัญญาณ** (กันกดพลาด) |
| 3 | กดค้าง ~1.5 วินาที | ไฟแดงกะพริบเร็ว + บี๊บ → ภายใน ≤ 10 วินาทีไฟแดง**ติดค้าง** = "ส่งถึงเซิร์ฟเวอร์แล้ว (L1)"; แดชบอร์ดมีเคสใหม่ + LINE ของ อสม. คนที่ 1 ได้ข้อความ |
| 4 | กด "รับเรื่อง" ใน LINE (หรือแดชบอร์ด) | ภายใน ≤ ~15 วินาที ไฟเขียวติด + บี๊บ 2 ครั้ง + OLED "STAFF ACCEPTED" |
| 5 | ไม่ตอบรับ อสม. คนที่ 1 เกิน 2 นาที | LINE คนที่ 2 ได้ข้อความ (ตามค่า escalation) |
| 6 | ปิดเคสเป็น "เหตุผิดพลาด" | ไฟเขียวกะพริบเร็ว, OLED FALSE ALARM |
| 7 | กดค้างตอนรอ (≤45 วินาทีหลังกด) นาน ~4.5 วินาที | ยกเลิก: ไฟแดง+เขียวพร้อมกัน, เคสเป็น "ยกเลิกโดยผู้ป่วย" |
| 8 | กดสั้น 3 ครั้งติดกัน | โหมดทดสอบ: ไฟเขียวกะพริบ + OLED TEST OK; เคสทดสอบ**ไม่ส่ง LINE** |
| 9 | ปิด gateway แล้วกดค้าง | ไฟแดงกะพริบเร็ว + OLED "NOT SENT! CALL 1669" ภายใน ~60 วินาที (อุปกรณ์ยังลองส่งซ้ำเบื้องหลัง) |
| 10 | ถอดปลั๊กไฟ USB (ใช้แบต) | ภายใน 1 รอบ heartbeat แดชบอร์ดแสดง "ไฟดับ"; (ย่นรอบ heartbeat ชั่วคราวในหน้าตั้งค่าเพื่อทดสอบ) |
| 11 | แก้ "ค่าเริ่มต้นอุปกรณ์" ในหน้าตั้งค่า | อุปกรณ์รับ CONFIG ภายใน 1 รอบ heartbeat (ดู log ว่า cfg_ver เปลี่ยน) |
| 12 | กดนอกเวลาราชการ (เปลี่ยนเวลาทำการเพื่อจำลอง) | OLED "AFTER HOURS / CALL 1669 NOW" + ไฟแดงค้าง; LINE ยังส่งถึง อสม. |
| 13 | จ่ายไฟออก/เข้าตอนกำลังมีเคส | บอร์ดรีบูตแล้ว join ใหม่ได้เอง (เคสเดิมยังอยู่ในแดชบอร์ด) |
| 14 | ทิ้งไว้ 24 ชม. | heartbeat ต่อเนื่อง ไม่หลุด; บันทึกแบตและ RSSI |

ช่วงทดสอบเร็ว: เปิด `-D SOS_DEBUG_FAST_TIMERS=1` ใน `platformio.ini` (**ปิดก่อนใช้งานจริง**)

## 6. ความหมายของไฟ/เสียง (ใช้อบรมผู้ป่วย/อสม.)
| สถานะ | ไฟ | เสียง |
|---|---|---|
| พร้อมใช้ | เขียววาบสั้นทุก 5 วินาที | – |
| กำลังส่ง | แดงกะพริบเร็ว | บี๊บสั้นเป็นระยะ |
| ส่งถึงระบบแล้ว รอเจ้าหน้าที่ | แดงติดค้าง | บี๊บสั้น 3 ครั้ง |
| ส่งไม่สำเร็จ (>60 วิ) | แดงกะพริบเร็ว | บี๊บเป็นระยะ → **โทร 1669** |
| เจ้าหน้าที่รับเรื่อง | เขียวติด | บี๊บ 2 ครั้ง |
| ปิดเคส | เขียวกะพริบช้า | บี๊บ 2 ครั้ง |
| นอกเวลาราชการ | แดงติด + เขียววาบ | บี๊บยาว 3 ครั้ง → **โทร 1669** |

## 7. ข้อจำกัดที่ต้องรู้ / งานต่อ
- รีบูตแล้ว **join ใหม่เสมอ** (เก็บ DevNonce ไว้ใน NVS) เพื่อเลี่ยงปัญหา frame counter ตกหลัง ไฟดับ — ใช้เวลา join ~10–30 วินาที
- จอ OLED แสดงภาษาอังกฤษ/ตัวเลข (ฟอนต์ไทยบน U8g2 ยังไม่ได้ตรวจ) · ข้อความไทยส่งผ่าน LINE/แดชบอร์ด
- Class A: อุปกรณ์ "ถาม" (ALERT_POLL ทุก 10 วินาที) แทนการรอรับ จึงใช้แบตมากกว่าโหมดสลีป → ใช้ไฟบ้านเป็นหลัก แบตเป็นสำรอง (deep-sleep/Class C เป็นงานหลังนำร่อง)
- ก่อนผลิตจำนวนมาก: เปิด flash encryption/secure boot ของ ESP32-S3 (กุญแจ AppKey เก็บใน NVS ไม่ได้เข้ารหัสในรุ่นนี้), ทำ OTA (ยังไม่มี), ตั้ง brown-out/ watchdog ตามผลทดสอบจริง
- ตรวจกฎ กสทช. (กำลังส่ง/ย่านความถี่ AS923 ในไทย) และการขอรับรองก่อนใช้งานในวงกว้าง
