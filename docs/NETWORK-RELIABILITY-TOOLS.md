# เครื่องมือดูแลเครือข่าย LoRaWAN

## หน้าเกตเวย์

ตารางสถิติแสดงจำนวนเฟรมที่ ChirpStack ระบุว่าแต่ละเกตเวย์ได้รับ, จำนวนปุ่มที่ได้ยิน, RSSI/SNR เฉลี่ย และแนวโน้มรายวัน เลือกช่วงย้อนหลัง 7, 30 หรือ 90 วันได้ ค่าที่เก็บก่อนเปิดใช้การบันทึก `rxInfo` จะไม่ถูกสร้างย้อนหลัง

“สัดส่วนเฟรมเครือข่ายที่ได้ยิน” เทียบจำนวนเฟรมที่เกตเวย์นั้นได้รับกับจำนวน uplink ทั้งระบบในช่วงเดียวกัน เป็นสัดส่วนการมีส่วนร่วมของเกตเวย์ ไม่ใช่การรับประกันว่า downlink/ACK จะส่งถึงปุ่ม

## เฟรม LoRaWAN สด

เมนู “เฟรม LoRaWAN สด” แสดง 100 uplink ล่าสุดและรับรายการใหม่ผ่าน WebSocket ใช้ดูเวลา, FCnt, FPort, RSSI/SNR, SF, ความถี่ และ Gateway ID เท่านั้น ระบบไม่ส่ง payload ของผู้ป่วยไปที่หน้านี้ ประวัติ uplink เก็บไม่เกิน 90 วัน

## Device Profile

ผู้ดูแลระบบเปลี่ยนได้เฉพาะ ADR algorithm จากรายการที่ ChirpStack ส่งกลับมา ค่าอื่นใน Device Profile ไม่ถูกแก้ ส่วนเวลา offline ของปุ่มตั้งได้ที่ “ตั้งค่า → ออฟไลน์”

ChirpStack จะปรับ data rate / กำลังส่งด้วย ADR เมื่ออุปกรณ์ส่ง uplink โดยเปิด ADR flag; อ่าน [เอกสาร ChirpStack เรื่อง Adaptive Data Rate](https://www.chirpstack.io/docs/chirpstack/features/adaptive-data-rate.html) ก่อนเปลี่ยนค่าบนเครือข่ายจริง

## สำรองและกู้คืน ChirpStack

ผู้ดูแลระบบส่งออก Device, Gateway และ keys ใน Application ที่กำหนดไว้เป็นไฟล์ JSON ซึ่งเข้ารหัสด้วย AES-256-GCM และสร้างกุญแจจากรหัสผ่านด้วย scrypt รหัสผ่านต้องยาวอย่างน้อย 16 ตัวอักษร เก็บรหัสผ่านแยกจากไฟล์

การนำเข้าใช้ Application, Device Profile และ Tenant ที่ตั้งค่าบนเซิร์ฟเวอร์ปลายทาง หาก DevEUI หรือ Gateway ID มีอยู่แล้ว ระบบจะอัปเดตข้อมูลนั้น รวมถึง Device keys; อุปกรณ์ที่ยังใช้ keys เก่าอาจเชื่อมต่อไม่ได้ การนำเข้าเป็นรายการต่อรายการ หากบางรายการผิดพลาด รายการก่อนหน้าที่สำเร็จจะยังคงอยู่และหน้าเว็บจะแสดง ID ที่ล้มเหลว

ไฟล์นี้สำรองเฉพาะข้อมูล ChirpStack ที่ระบุข้างต้น ไม่รวมฐานข้อมูล SOS, ผู้ใช้, การตั้งค่า, case history หรือสถานะ session ของอุปกรณ์
